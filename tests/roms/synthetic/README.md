# Synthetic input-tester fixture

This directory contains our own tiny GBA fixture, not a retail ROM, BIOS image,
save file or vendored binary. It exists so the native AOT and browser paths can
prove real `KEYINPUT` handling and a deterministic frame.

| File | SHA-256 | Purpose |
| --- | --- | --- |
| `input-tester.gba` | `8a7667d43d9ec0333a5a7c0a032837919e101ca1c1893bdf5f95f51b27555539` | 4 KiB Mode 3 fixture, generated by `gba-native fixture input-tester` |
| `input-tester.input` | — | Holds A+B+Start for the whole run |
| `input-tester.expected.ppm` | `2824c8e9f509c1294c555af3318cec4d3fd4a37aa964f60e9ecc974721da941a` | Expected final 240x160 frame |

The guest draws ten horizontal 16-pixel bands in KEYINPUT order
(`A,B,Select,Start,Right,Left,Up,Down,R,L`). A band is white while its button is
held and dark otherwise. With A+B+Start held, bands 0, 1 and 3 are white and the
rest are dark. The expected image SHA-256 (RGB888) is
`5cbbd998a2bc5a026ebac07d91a0f058b769cb05dd14c09e30d52888ed80db8b`.

At boot the guest also enables the master sound register and programs a 440 Hz
square tone on channel 1. Running with `--audio-out` writes a WAV from the
sound-register timeline; the reference 2,000,000-instruction run produced 11,718
samples with `audio_audible=true`. The tone is a synthetic fixture signal, not a
retail soundtrack or hardware-audio claim.

Generate and run locally:

```sh
cargo run -- fixture input-tester --out output/input-tester/input-tester.gba
cargo run -- run output/input-tester/input-tester.gba --budget 20000000 \
  --input tests/roms/synthetic/input-tester.input --out output/input-tester-run
cargo run -- run output/input-tester/input-tester.gba --budget 2000000 \
  --audio-out output/input-tester-run/tone.wav --volume 80
```

`crates/core/tests/input_tester_fixture.rs` regenerates the bytes, checks the
committed digest, runs the reference interpreter and compares the frame with
both the committed PPM and the independent expected-image function. The Linux
CI job additionally builds the same fixture through native AOT, runs the
generated executable with the input script and compares the actual frame with
the committed expected image.

This is fixture evidence for the input path only: not hardware conformance,
cycle timing, retail-game compatibility or a playability claim.
